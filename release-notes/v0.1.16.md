# v0.1.16

## Migration Framework

The sync system now supports automatic chain-based migrations:

- Migration scripts in `bootstrap/migrations/` are discovered by filename pattern `X.Y.Z_to_A.B.C.sh`
- The runner builds a shortest-path chain from the installed version to the current version using BFS
- Multi-step migrations execute in order (e.g., `0.1.0 → 0.1.1 → 0.1.16`)
- Unknown version transitions fall back gracefully to managed sync

### Adding a Migration

1. Create `bootstrap/migrations/<from>_to_<to>.sh` accepting `$1` as target directory
2. The chain runner will discover and use it automatically
3. No need to edit `common.sh` or any case statements

### Current Migration Chain

```
0.1.0 → 0.1.1: manifest directory and project.yaml creation
0.1.1 → 0.1.16: commands.yaml, environment.yaml, experience directories
```

## CURRENT_AI_VERSION

The `CURRENT_AI_VERSION` constant in `bootstrap/common.sh` now tracks the actual release version instead of being stuck at 0.1.1. This ensures sync correctly detects when projects need upgrading.
