# v0.1.15

## Weighted Stack Detection

Stack detection now uses a two-tier scoring model:

- **`match_primary`**: unique stack markers scored at 3x weight (e.g., `go.mod` for Go, `app/main.py` for FastAPI)
- **`match_any`**: common markers scored at 1x weight (e.g., `pyproject.toml`, `package.json`)
- **`priority`**: numeric tie-breaker when scores are equal (lower wins)

This prevents generic stacks (node, python) from winning over specific stacks (nextjs, fastapi) when both share common markers.

## Priority Tiers

| Priority | Stacks | Role |
|----------|--------|------|
| 10 | flutter, nextjs, react-native, go-service, fullstack-monorepo | Unique primary markers |
| 15 | fastapi, data-ml | Specific Python stacks |
| 20 | python-service | Service-shaped Python |
| 30 | ops-dashboard | Mixed-signal catch |
| 90 | node, python | Generic catch-all fallbacks |

## Detection Tests

Smoke tests now include explicit detection assertions:
- FastAPI project with `app/main.py` + `pyproject.toml` correctly detected as `fastapi` (not `python`)
- Go project with `go.mod` + `cmd/` correctly detected as `go-service`
