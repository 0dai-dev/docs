# v0.3.5

## Spec-Driven Development Templates

Structured specifications in `ai/specs/` give agents precise context before starting work.

### Why Specs?

- Replace verbal descriptions with structured, reviewable documents
- Ensure agents understand context, constraints, and acceptance criteria
- Enable traceability between intent and implementation
- Support async workflows — write the spec, then hand it to any agent

### Spec Format

```yaml
---
id: SPEC-001
title: Add user authentication
status: draft|ready|in-progress|done|cancelled
priority: critical|high|medium|low
author: team-member
created: 2026-03-29
tags: [auth, security]
agent: architect
---

## Context
## Goal
## Requirements
## Acceptance Criteria
## Out of Scope
## Technical Notes
```

### Commands

```bash
# Create a new spec
0dai spec --new add-auth --title "Add Authentication" --priority high --agent architect --target .

# List all specs with status
0dai spec --list --target .

# Show spec details
0dai spec --info SPEC-001 --target .

# Validate all specs for completeness
0dai spec --validate --target .

# JSON output
0dai spec --json --target .
```

### MCP Tool

`get_specs` returns specs with optional status filtering. Agents should check for `ready` specs before starting work.

### Python SDK

```python
import zerodayai
all_specs = zerodayai.specs("/path/to/project")
ready = zerodayai.specs("/path", status="ready")
```

### Integration

- Specs directory (`ai/specs/`) created during `init-existing` and `sync`
- Ships with `TEMPLATE.md` and 2 example specs
- Validation checks: required frontmatter, required sections, acceptance criteria
- Auto-increments spec IDs (SPEC-001, SPEC-002, ...)
