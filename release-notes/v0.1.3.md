# v0.1.3

This release turns more of the 0dai operating model from documentation into executable workflow.

## Highlights

- `harvest` now converts normalized events from `ai/experience/outbox/` into archived events and candidate lessons.
- `promote` now moves reviewed candidates into accepted rules, skills, playbooks, and anti-patterns.
- Docker runtime support is hardened with explicit `trusted|untrusted` and `auto|init|sync|none` behavior in the runner entrypoint.
- The applied lock lifecycle, experience flow, and container runtime are now all part of the tested baseline.

## Major Changes

- Experience flywheel intake and promotion workflow
- Hardened Docker runner bootstrap behavior
- Better alignment between runtime, knowledge lifecycle, and canonical AI layer state

## Validation

- `python3 scripts/validate_templates.py`
- `bash tests/smoke_test.sh`

## Upgrade Note

Projects can continue to use `./bin/ai-repo sync --target <path>`, and teams can now begin capturing and promoting reusable knowledge through `harvest` and `promote` as part of the 0dai workflow.
