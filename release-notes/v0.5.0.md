# v0.5.0

## MCP Write Tools

Agents can now modify the ai/ layer through MCP, not just read it.

### New MCP Tools

| Tool | What It Does |
|------|-------------|
| `create_spec` | Create a new development spec in ai/specs/ with auto-incremented ID |
| `record_experience` | Record an experience event for the knowledge flywheel |
| `update_decision` | Append an Architecture Decision Record to decisions.md |

### create_spec

```
Input: title, goal, requirements, priority, agent
Output: { id: "SPEC-004", file: "ai/specs/SPEC-004-add-auth.md", status: "draft" }
```

Creates structured specs that agents (especially planner) read before starting work. Auto-increments SPEC-001, SPEC-002, etc.

### record_experience

```
Input: event_type, tool, task_type, summary, paths, ci_passed
Output: { event_id: "a1b2c3d4e5f6", file: "ai/experience/events/..." }
```

Feeds the experience flywheel: events → candidates → accepted knowledge. Agents record what they learned during task execution.

### update_decision

```
Input: title, context, decision, consequences
Output: { file: "ai/docs/decisions.md", title: "Use PostgreSQL" }
```

Append-only ADR log. Agents record architectural decisions made during implementation.

### Audit Trail

All write operations are logged to `ai/manifest/audit.jsonl` with `mcp-write:` prefix for traceability.

### 25 MCP Tools Total

22 read tools + 3 write tools. Write tools follow the "Read-first, Write-careful" principle — all mutations are audited.
