# v0.2.4

## Agent Personas

Four role-based personas give agents specialized context for different tasks:

| Persona | Focus | Review Checklist |
|---------|-------|------------------|
| **architect** | System design, module boundaries, ADRs | Boundary respect, dependency justification, API compatibility |
| **qa** | Test coverage, edge cases, regressions | Happy path + error tests, behavior over implementation |
| **devops** | CI/CD, containers, deployment safety | Pipeline impact, secret handling, rollback strategy |
| **security** | OWASP, access control, credential management | Input validation, secret storage, CVE-free deps |

### How Personas Work

Each persona provides:
- `system_prompt_addition` — injected into agent context for role-specific behavior
- `focus_paths` — directories the persona should prioritize
- `allowed_command_tiers` — which command tiers the role can use
- `review_checklist` — questions to verify before approving changes

### Usage

Personas are installed to `ai/personas/` during `init-existing` and `sync`.

Agents query available personas via MCP:
```
get_personas → { personas: [...], count: 4 }
```

Select a persona by including its `system_prompt_addition` in context.

### Custom Personas

Add custom personas to `ai/personas/custom-role.yaml` following the same schema.
Files without `managed: true` won't be overwritten during sync.
