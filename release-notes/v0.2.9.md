# v0.2.9

## Cross-Repo Knowledge Federation

Link related repositories (micro-services, mono-repo siblings) to share accepted experience knowledge.

### Commands

```bash
# Add a peer repo
0dai federation --target /my-service --add /path/to/peer-service

# Sync accepted knowledge from all peers
0dai federation --target /my-service --sync

# Show federation status
0dai federation --target /my-service

# Remove a peer
0dai federation --target /my-service --remove peer-name
```

### How It Works

1. Register peers via `--add` — stores in `ai/federation.yaml`
2. `--sync` copies accepted knowledge (rules, skills, playbooks, anti-patterns) from peers
3. Synced knowledge lands in `ai/experience/federated/<peer-name>/` — isolated from local
4. Agents can read federated knowledge to apply learnings from other services

### Federation Manifest

```yaml
managed: true

peers:
  - name: auth-service
    path: /workspace/auth-service
    added: 2026-03-28
    last_sync: 2026-03-28T08:30:00+00:00
  - name: payment-service
    path: /workspace/payment-service
    added: 2026-03-28
```

### MCP Tool

`get_federation` shows peers, reachability, sync status, and item counts.

### Privacy

- Only **accepted** knowledge syncs (reviewed and promoted)
- Raw events and candidates never leave their source repo
- Each peer's knowledge is namespaced to prevent conflicts
