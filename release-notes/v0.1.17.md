# v0.1.17

## Org Policy Packs

Organizations can now define and apply policy packs that override default 0dai behavior:

### What's in an Org Pack

```yaml
permissions:
  protected_paths: [".env*", "secrets/**"]
  denied_commands: ["rm -rf /"]
mcp:
  allowed_servers: [filesystem, github]
  require_explicit_approval: true
hooks:
  pre_deploy:
    command: "echo 'deploy requires approval'"
constraints:
  require_tests_before_deploy: true
  audit_log_enabled: true
```

### Usage

```bash
# Apply a specific org pack
0dai apply-policy --target /path/to/project --pack enterprise-default

# Apply all available org packs
0dai apply-policy --target /path/to/project

# Sync automatically applies org packs
0dai sync --target /path/to/project
```

### How It Works

- Org packs live in `templates/layer/ai/packs/org/<name>/<version>/pack.yaml`
- During `sync`, all org packs are automatically applied
- Applied policies are written to `ai/manifest/org-policy.json` for agents to read
- Policies merge with defaults, they don't replace them

### Shipped Pack

**enterprise-default** — security-hardened baseline:
- Protected paths: `.env*`, `secrets/`, `credentials/`, `terraform.tfstate*`
- Denied dangerous shell patterns
- Deploy/migrate commands require ops tier approval
- MCP server allowlist enforcement
- Audit logging and review requirements
