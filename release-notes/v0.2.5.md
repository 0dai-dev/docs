# v0.2.5

## Custom Stack Extensibility

Projects can now define their own stacks without modifying 0dai upstream.

### How It Works

Place YAML detector files in `ai/stacks/` in your project:

```yaml
# ai/stacks/my-monolith.yaml
name: my-monolith
priority: 5
match_primary:
  - src/main/java/
  - pom.xml
match_any:
  - docker-compose.yml
recommended_layout: custom
agents:
  - codex
  - claude
```

Custom stacks:
- Take **priority** over upstream detectors (scanned first)
- Use the same weighted scoring engine (match_primary 3x, match_any 1x)
- Are preserved during `0dai sync` (not overwritten)
- Are queryable via `get_custom_stacks` MCP tool

### Priority Guidelines

| Range | Purpose |
|-------|---------|
| 1-9 | Project-specific custom stacks (highest priority) |
| 10-30 | Specific upstream stacks (nextjs, flutter, go-service) |
| 50 | Default |
| 90 | Generic catch-all (node, python) |

### MCP Tool

Agents can discover custom stacks:
```
get_custom_stacks → { stacks: [{name, priority, recommended_layout}], count: N }
```
