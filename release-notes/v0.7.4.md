# v0.7.4

## Cloud Authentication

Team features now require `0dai auth login` instead of an offline license file.

### Auth Flow

```bash
$ 0dai auth login
[0dai] Authenticate with 0dai Cloud

  1. Go to: https://api.0dai.dev/auth
  2. Sign in or create an account
  3. Copy the auth code (format: XXXX-YYYY)

[0dai] Paste auth code: TEST-1234
[0dai] authenticated as dev@example.com
[0dai] team: Demo Team
[0dai] plan: team (10 seats)
```

### How It Works

- `0dai auth login` — authenticate via browser-based code
- Token stored at `~/.0dai/auth.json` (chmod 600)
- Token valid for 7 days offline, auto-refreshes when online
- Core CLI works WITHOUT auth (init, sync, doctor, detect, serve, harvest, promote, search)
- Team features REQUIRE auth (kb, activity, role-policy, conflicts, federation)

### Commands

| Command | Description |
|---------|-------------|
| `auth login` | Authenticate with auth code |
| `auth login --code XXXX-YYYY` | Non-interactive login |
| `auth status` | Show current auth state |
| `auth logout` | Remove token |
| `auth --json` | JSON output |

### Migration from License

The old `ai/manifest/license.json` offline license is replaced by `~/.0dai/auth.json` cloud token. Existing license files are ignored. Run `0dai auth login` to authenticate.

### Why This Change

- Offline JWT was trivially bypassable (honor system)
- No usage data = blind product development
- Cloud auth enables: analytics, team management, billing
- Core stays free and offline — no regression for solo developers
