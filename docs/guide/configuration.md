# Configuration

After running `0dai init`, your project contains an `ai/` directory and several agent-specific config files. This page explains each one.

## Directory Structure

```
your-project/
  ai/
    manifest/
      project.yaml
      commands.yaml
      discovery.json
    personas/
    playbooks/
  CLAUDE.md
  AGENTS.md
  opencode.json
```

## ai/manifest/project.yaml

Project metadata consumed by all agents. Contains:

- **name** -- project identifier
- **stack** -- primary languages, frameworks, and runtimes
- **team** -- contributor roles and ownership
- **goals** -- current project objectives

Example:

```yaml
name: my-app
stack:
  languages: [typescript, python]
  frameworks: [next, fastapi]
  package_managers: [npm, pip]
goals:
  - Ship v2 billing integration
  - Improve test coverage to 80%
```

## ai/manifest/commands.yaml

Classifies your project's build, test, lint, and dev commands into tiers so agents know which commands are safe to run autonomously.

Example:

```yaml
tiers:
  safe:
    - npm run lint
    - npm test
  needs_approval:
    - npm run deploy
  destructive:
    - npm run db:reset
```

## ai/manifest/discovery.json

Auto-generated by `0dai detect`. Contains the detected stack, entry points, dependency graph, and file tree summary. This file is regenerated on each `sync` or `detect` run.

## ai/personas/

Agent persona definitions that shape how each AI agent approaches your codebase. Personas can specify coding style, review strictness, and domain expertise.

## ai/playbooks/

Reusable task playbooks that agents can follow for common workflows (e.g., "add a new API endpoint", "fix a failing CI pipeline").

## Native Agent Config Files

0dai generates config files that each agent reads natively:

| File | Agent | Purpose |
|---|---|---|
| `CLAUDE.md` | Claude Code | Project context, rules, file map |
| `AGENTS.md` | Codex | Agent instructions and constraints |
| `opencode.json` | OpenCode | Model config and project metadata |
| `GEMINI.md` | Gemini | Project context for Gemini CLI |
| `.aider.conf.yml` | Aider | Aider-specific settings |
| `qoder.yaml` | Qoder | Qoder agent configuration |

These files are kept in sync by running `0dai sync`.

## Updating Configuration

After changing your project's dependencies or structure:

```bash
0dai sync
```

To preview changes without writing files:

```bash
0dai sync --dry-run
```

To suppress output during sync:

```bash
0dai sync --quiet
```
