# 0dai

**Stop duplicating AI agent configs 5 different ways.**

One `ai/` directory. Five agent CLIs. Auto-synced.

Your team uses Claude Code, Codex, OpenCode, Gemini, and Aider — each with its own config format. 0dai generates all of them from a single source of truth, so your project knowledge stays in one place and every agent reads it natively.

## What 0dai Does

1. **Installs** a non-destructive `ai/` layer into any existing repository.
2. **Detects** your stack (FastAPI, Next.js, Flutter, Go, and 5 more).
3. **Generates** native configs for every agent CLI you use.
4. **Syncs** changes — edit `ai/`, run `sync`, all agents update.
5. **Captures** team experience into searchable knowledge that agents learn from.

## Quick Start

Create a new repo skeleton:

```bash
./bin/0dai init-new --stack flutter --agents codex,claude,opencode --target /path/to/project
```

Install into an existing project:

```bash
./bin/0dai init-existing --target /path/to/project
```

Sync managed configs later:

```bash
./bin/0dai sync --target /path/to/project
```

Validate an installed AI layer:

```bash
./bin/0dai validate --target /path/to/project
```

Explain the current environment and command policy:

```bash
./bin/0dai doctor --target /path/to/project
```

Harvest normalized experience events into candidate knowledge:

```bash
./bin/0dai harvest --target /path/to/project
```

Promote reviewed candidates into accepted knowledge:

```bash
./bin/0dai promote --target /path/to/project
```

Record normalized task events into the experience outbox:

```bash
./bin/0dai task run --target /path/to/project --tool claude --task-type bugfix --summary "reset seeded fixtures before auth tests" --candidate-type skill --paths services/api/** -- bash -lc "pytest tests"
```

Inspect detected environment:

```bash
./bin/0dai detect --target /path/to/project
```

## What Gets Installed Into Projects

- `ai/` as the project-local AI operating layer.
- Root agent configs such as `AGENTS.md`, `CLAUDE.md`, `.codex/config.toml`, `.claude/settings.json`, `opencode.json`, `.opencode/agents/`, `.gemini/settings.json`, `.gemini/agents/`, `.mcp.json`.
- Stack-specific docs, prompts, playbooks, and patterns.
- `ai/VERSION` and `ai/meta/project.manifest.yaml` for controlled sync.
- Hook scripts in `ai/bootstrap/hooks/` and a CI recipe in `.github/workflows/ai-layer-check.yml`.

## Recommended Operating Model

- Keep this repository as the upstream template and tooling source.
- Install `ai/` into each product repository.
- Treat files with `managed: true` markers as generated by this toolkit.
- Store project-specific decisions inside the project-local `ai/docs/` instead of modifying upstream templates unless the change should be shared globally.

## Tooling Model

- `Codex`: project config lives in `.codex/config.toml`, with root `AGENTS.md` as the durable repo guide.
- `Claude Code`: project config lives in `.claude/settings.json`, with root `CLAUDE.md` and optional `.mcp.json`.
- `OpenCode`: project config lives in `opencode.json` plus `.opencode/agents/default.yaml`.
- `Gemini CLI`: project config lives in `.gemini/settings.json` plus `.gemini/agents/`.
- Shared knowledge lives once in `ai/`; tool-specific files only point agents toward it.

## Container Runtime

- compose: `docker-compose.ai.yml`
- workspace image: `docker/ai-runner/Dockerfile`
- devcontainer: `.devcontainer/devcontainer.json`

Start the standard workspace runtime:

```bash
docker compose -f docker-compose.ai.yml up --build ai-runner
```

Run isolated agent phase without network:

```bash
docker compose -f docker-compose.ai.yml --profile isolated run --rm ai-runner-isolated
```

Useful runtime env flags:

- `ODAI_TRUST_MODE=trusted|untrusted`
- `ODAI_BOOTSTRAP_MODE=auto|init|sync|none`

Starter environment file:

```bash
cp .env.ai.example .env.ai
```
